= How We Work

Spring LDAP is developed in the open, and these pages explain how: how issues are triaged, how a change finds its way into the right branches, and how a release happens.

The goal is education and transparency.
If something here looks wrong, unclear, or like it could be done better, please https://github.com/spring-projects/spring-ldap/issues[open an issue] or a pull request.

[TIP]
====
Looking for step-by-step instructions instead?

* To contribute, see link:../CONTRIBUTING.adoc[CONTRIBUTING.adoc].
* Maintainers preparing a release should see link:../RELEASE.adoc[RELEASE.adoc].
====

== 👥 Who Should Read What

* *Contributors* will mostly want link:issues-and-prs.adoc[Issues and Pull Requests], link:issue-types.adoc[Types of Changes], and the first part of link:merging.adoc[Merging Changes].
* *The curious* may enjoy all of it.
* *Maintainers* will also want link:releasing.adoc[Releasing] and the rest of link:merging.adoc[Merging Changes].

== 🗺️ How These Pages Are Organized

Each page here has the same shape:

. 🎯 *Purpose* -- what the page explains and who it is for
. 📚 *Prerequisites* -- the pages to read first
. The explanation itself
. 🔍 *Examples* -- where one helps
. 🔗 *See Also* -- where to go next

A term is explained once, in the page that owns it, and linked from everywhere else.
The link:glossary.adoc[glossary] collects them all.
